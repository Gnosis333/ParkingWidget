# Parking Memory Widget

지하 주차장에서 **어느 층(B1/B2)에 주차했는지 자동으로 기억**하는 안드로이드 홈 화면 위젯.

주머니 속에서 폰을 꺼내지 않아도, 주차 후 걸어 나오는 동안 BLE 스캔으로 층을 감지해
위젯에 표시한다. 수동 탭으로 층을 바꾸는 것도 가능하다.

## 동작 원리

아파트 도어 비콘(스마트 IoT 원패스)은 1층/2층이 동일 UUID이고 MAC을 30~40분마다
회전시켜 층 구분에 쓸 수 없다. 대신 **층마다 고유하게 존재하는 고정-MAC BLE 기기를
"앵커"로 사용**한다 (`ParkingAnchors.kt` — 층 판정 단일 출처):

- B1 앵커: 삼성 기기, keybox
- B2 앵커: LC241 조명 컨트롤러 3대

`BleMonitorService`(포그라운드 서비스)가 앵커 광고를 상시 스캔하고, 최근 30초 내
가장 강한 앵커의 층으로 판정해 위젯을 갱신한다.

**주차 순간은 차량 블루투스로 안다.** 차량 오디오(핸즈프리) 링크가 끊기는 시점 =
시동 끔 = 주차 완료다. 이때 90초 집중 스캔을 걸고, 그래도 앵커를 못 잡으면 위젯은
지난 주차 건의 값을 확정인 척 보여주지 않고 **"미확인"(호박색 `2F?`)** 으로 표시한다.

## 구성

| 파일 | 역할 |
|------|------|
| `ParkingWidgetProvider.kt` | 홈 위젯 렌더링·탭 처리, 서비스 시작/중지 |
| `BleMonitorService.kt` | 상시 BLE 스캔, 층 판정, 주차 이벤트 처리, 자가치유·워치독 |
| `ParkingAnchors.kt` | 앵커 MAC/이름 목록 + 층 매핑 (단일 출처) |
| `ParkingState.kt` | 층 값 + 주차/확정 시각 (위젯·서비스 공유 단일 출처) |
| `CarReceiver.kt` | 차량 오디오 링크 판별 + 서비스 사망 시 주차 이벤트 백업 경로 |
| `WatchdogReceiver.kt` | AlarmManager 워치독 수신 (Doze 대응 부활) |
| `MonitorLog.kt` | 서비스 진단 로그 (`monitor_log.txt`, 256KB 캡) |
| `BootReceiver.kt` | 부팅·앱 업데이트 후 서비스 재시작 |
| `MainActivity.kt` | BLE 디버그 콘솔 (수동 스캔·로그 저장·권한/상태 안내) |

## 안정성 설계 (5중)

백그라운드 BLE 스캔은 조용히 죽는 경로가 많다. 이 앱은 4일간의 실전 디버깅으로
확인된 함정들을 모두 방어한다:

1. **위치 "항상 허용" 필수** — BLE 스캔 결과는 위치 정보로 취급되어, 위치 권한이
   "앱 사용 중에만"이면 백그라운드에서 결과가 에러 없이 전량 차단된다.
2. **주소 타입 함정** — `ScanFilter.setDeviceAddress(mac)`는 PUBLIC 주소를 가정해
   랜덤 주소로 광고하는 앵커에 안 걸린다 → 기기 **이름 필터를 병행**하고 콜백에서
   MAC으로 재검증.
3. **Doze 워치독** — Handler 타이머는 깊은 잠에서 멈추므로, AlarmManager
   `setAndAllowWhileIdle` 15분 체인으로 죽은 서비스도 부활시킨다.
4. **스캔 자가치유** — `onScanFailed` 백오프 재시작, 20분 주기 stop→start,
   화면 켜짐 시 무필터 버스트 스캔(25초).
5. **주차 이벤트 트리거** — 화면 켜짐에만 의존하면 주머니에 넣고 걸어 나오는 동안
   집중 스캔이 아예 안 걸린다. 차량 BT 해제 순간 스캔 강제 재시작 + 90초 무필터
   버스트(부분 웨이크락)로 관측 창을 확보한다. 서비스가 죽어 있으면 매니페스트
   `CarReceiver`가 서비스를 깨워 이어받는다.

## 값이 낡았을 때: "미확인" 표시

앵커를 못 잡으면 판정이 아예 실행되지 않으므로, 예전엔 **지난 주차 건의 층이
아무 표시 없이 그대로 남아** 있었다 (2026-09-10: 15:47 B1 주차가 정상 판정된 뒤
20:35 B2 주차에서 앵커 0건 → 위젯은 7시간 전 "지하1층"을 계속 표시).

`ParkingState`가 **주차 시각**과 **층 확정 시각**을 따로 남겨 이를 구분한다:

- 주차 후 3분(`UNCONFIRMED_GRACE_MS`) 안에 확정되면 → 평소대로 초록 확정 표시
- 확정이 없으면 → 호박색 점선 + `2F?` (탭해서 직접 고르라는 신호) + 알림
- 수동 탭·자동 판정 어느 쪽이든 확정으로 인정되어 표시가 풀린다
- 출차(차량 BT 연결) 시 미확인 표시는 자동으로 내려간다

앱 상태창 맨 아랫줄에 `표시 층 / 주차 시각 / 확정 시각`이 한 줄로 나온다.

## 설치 후 필수 설정

1. 앱 실행 → **"백그라운드 자동감지 켜기"** 버튼.
2. 위치 권한 **"항상 허용"** 선택 (안 하면 백그라운드 감지 불가 — 상태창에 표시됨).
3. 배터리 최적화 예외 허용.

## 진단

문제 발생 시 서비스 로그 회수:

```
adb pull /sdcard/Android/data/com.example.parkingwidget/files/monitor_log.txt
```

서비스 생명주기·스캔 시작/실패·워치독 발화·앵커 수신(경로 태그)·주차/출차 감지·
층 판정이 모두 기록된다. 앵커 기기가 교체되면 "앵커 MAC 변경 의심" 로그로 새 MAC을
알 수 있다. 수동 스캔 로그(전파 전수 조사)는 앱의 "1층/2층 스캔" 버튼 → `scan_log.txt`.

**"앵커가 안 잡힌 것"과 "스캔이 죽은 것" 구분법**: `주차 감지` 로그 직후의
`버스트 스캔 종료 (기기 N종, 앵커 M건)`을 본다. 기기 수백 종 + 앵커 0건이면 스캔은
건강하고 그 자리에 앵커가 없는 것(= 커버리지 구멍, 새 앵커 등록 필요), 기기 0종이면
스캔이 차단·좀비 상태다. 시스템 쪽 교차 확인은
`adb shell dumpsys bluetooth_manager`의 `LE Scanner Map` (스캔별 Results 수치)과
차량 `ACTION_ACL_CONNECTED/DISCONNECTED` 기록.
